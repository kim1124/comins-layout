## 결과

- active target layout은 GridStack의 전체 drop snapshot을 보존하고 widget 배열 순서는 기존 controlled state 계약을 유지한다.
- 기존 inactive column cache에는 신규 widget을 deterministic first-available geometry로 추가한다.
- responsive layout 제한값이 현재 target geometry보다 크더라도 기존 column-cache 계약대로 보존한다.
- 기존 `addWidget()`의 동일 ID 교체 동작은 변경하지 않고 신규 transfer 경로만 중복 ID를 거부한다.
- GridStack은 source callback ref가 실제 DOM에 연결된 뒤에만 dynamic import되며 SSR 렌더에서는 평가되지 않는다.
- palette factory는 drag 시작마다 한 번 실행되고 source와 clone에서 동일 candidate를 조회할 수 있다.
- GridStack raw helper/start/stop callback은 외부에 노출하지 않고 package-owned lifecycle로 고정했다.
- target은 adapter-owned `acceptWidgets` bridge만 사용하며 consumer predicate, 중복 ID, source 상태를 enter와 drop 시점에 fail-closed 재검증한다.
- 임시 target snapshot의 `change` commit을 차단하고 target engine 정리, Grid source DOM 복원 또는 palette clone 제거, target controlled sync 순서로 rollback한다.
- callback 미등록·예외 상황에서도 rollback을 먼저 완료하며 consumer에는 serializable operation ID와 전체 target snapshot을 전달한다.
- Playground는 palette drag와 버튼이 동일 factory와 pure insertion helper를 사용하고 Grid 간 버튼과 pointer drag가 동일 transfer helper를 사용한다.
- 실제 pointer/touch drag는 accepted geometry를 controlled state에 반영하며 move는 source를 제거하고 copy는 source를 유지한다.
- predicate/duplicate 거부는 widget count를 변경하지 않고 route 전환 후 stale draggable 또는 duplicate callback이 남지 않는다.
- 최초 Chromium 및 Mobile Chrome 실패는 Grid 중앙이 실제 viewport 밖에 있던 테스트 좌표 문제였으며, 제품 계약을 낮추지 않고 visible target과 target scroll을 사용하도록 수정했다.
