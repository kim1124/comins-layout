## 원인과 변경

### GridStack 동기화 성능

GridStack 13.1 이후의 DOM 정렬 동작이 controlled snapshot의 위젯별 update마다 반복되었다. 100개 위젯을 `12 -> 6 -> 12` 컬럼으로 전환하는 재현에서 직접 자식 DOM 삽입 횟수는 14,600회였다. 새 회귀 assertion의 상한 400회를 실제로 초과하는 RED 결과를 확인했다.

어댑터의 `syncGridWidgets` 전체를 공개 `batchUpdate()` API로 묶었다. 이미 외부 batch가 열린 경우에는 그 batch를 종료하지 않으며, `finally`에서 이번 동기화가 연 batch만 닫는다. GridStack의 정상 DOM 정렬 동작은 유지한다. 수정 후 같은 재현은 200회이며 resource 검증은 16.2초에 통과했다.

기존 PR의 CI trace에는 browser console/page error 없이 컬럼 선택 94회가 성공한 기록이 있었고, select 작업 중앙값은 약 1,073ms였다. 120초 timeout을 UI control 누락으로 분류하지 않았다. 시간은 실행 환경에 의존하므로 새 회귀 계약은 DOM 삽입 횟수로 고정했다.

### 브라우저 테스트 계약

- `.first()` / `.nth()`로 계속 조회하면 DOM 정렬 후 다른 위젯을 검증하게 되므로, 초기화가 완료된 시점의 `data-testid`를 고정한다.
- 반응형 초기화 완료는 DOM의 controlled 좌표와 GridStack node 좌표 및 현재 컬럼이 일치하는지 확인한다.
- 드래그 전 source와 target 중심이 viewport 내부인지 검증한다. 초기 실패 trace에서는 잘못 선택된 target으로 스크롤한 뒤 source 중심이 화면 밖으로 이동한 사실을 확인했다.
- 컬럼별 cache는 ID로 정렬하여 비교하되 모든 위젯 ID와 좌표/크기 값, 서로 다른 컬럼 cache의 독립성 assertion은 유지한다.
- 기존 100-widget resource 검증에 DOM 삽입 상한을 추가했다. 반복 횟수, heap/node/listener/document 안정성 기준 및 120초 timeout은 완화하지 않았다.

### 의존성 및 notices

- 세 PR의 직접 의존성 버전을 통합했다. GridStack 13.2.0, lucide-react 1.40.0, Vite 8.2.2, React/React DOM 19.2.8, Vitest 5.0.0을 포함한다.
- 직접 의존성을 새로 추가하지 않았고 React peer 범위 `>=18.0.0 <20.0.0`도 유지했다.
- React/React DOM 19.2.8 package metadata의 repository는 `react/react`다. 19.2.7과 MIT license 본문이 동일함을 비교하고 notices의 source/license URL만 갱신했다.
- 실제 package tarball을 사용한 분리 fixture에서 이전 notices가 checker를 실패시키고 수정한 notices가 통과함을 확인했다. license checker는 변경하지 않았다.
