# 0.1.6 Service-Identity Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `comins-grid-layout@0.1.6` as the first version closed by the Comins service-identity gate, without changing runtime behavior or public APIs.

**Architecture:** Prepare only the version, support table, changelog, and value-free release evidence on a branch based on the merged identity-gate `main`. Reuse the existing full browser, consumer, exact-artifact, Gitleaks, OIDC staged-publishing, maintainer 2FA, and exact-version identity gates without rebuilding or mutating the verified archive.

**Tech Stack:** npm, Node.js 24, TypeScript, Vitest, Playwright, GridStack, GitHub Actions, npm trusted publishing/OIDC, Gitleaks 8.30.1

## Global Constraints

- Release exactly `0.1.6`; set only the root versions in `package.json` and `package-lock.json`.
- Treat the user instruction `다음 단계 진행` as approval for local release preparation and verification only.
- Do not push, create or merge a pull request, dispatch the staging workflow, approve a staged package, publish, deprecate, unpublish, create a tag or GitHub Release, mutate provider settings, or delete a branch/worktree without the operation-specific approval.
- Keep npm email, ownership, and trusted-publisher configuration frozen from the accepted current-owner check through exact-version closure.
- Never print or commit the service email, recovery address, credentials, tokens, OTPs, recovery codes, or value-derived fingerprints.
- Preserve Contract v1.4, the two repository-secret identity inputs, the two pre-stage identity checks, and constant value-free failure output.
- Preserve runtime dependencies, public APIs/types, CSS, GridStack behavior, and the exact-artifact transfer path.
- Record that React Router `8.3.0` and PostCSS `8.5.24` are already-merged development-tooling updates; do not change dependency resolutions during release preparation.
- License impact for the release metadata change is `N/A`; nevertheless run the existing license and exact-artifact gates because this is an actual public-release candidate.
- Run `npm run verify:full` exactly once after release metadata is complete. If it fails, classify the cause before any rerun.
- Create the package archive exactly once for local artifact closure, then use that same archive for extraction, Gitleaks, and React 18 consumer smoke.
- Keep versions `0.1.0` through `0.1.5`, the `0.1.0` legacy artifact risk, and public-profile remediation as separate provider risks.
